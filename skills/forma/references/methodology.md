# Design methodology

Start from the user's problem and one primary action. Read the real interface, brand, content, or reference before inventing a style. A recreation preserves hierarchy, geometry, typography, assets, and states; an exploration varies intentional dimensions such as density, navigation, tone, or motion.

Write a concise direction: audience, task, visual language, and how success will be checked. For an unconstrained brief, choose a specific direction and explain the assumption. Do not apply a provider's brand palette by default.

Establish a spacing scale, type hierarchy, surface palette, radii, and content width. Use CSS custom properties for repeatable decisions. Typography must fit the content, with comfortable line lengths and meaningful contrast. Avoid generic gradients, oversized rounded containers, stock slogans, and decorative controls unless the brief supports them.

Build the essential content first. Keep source understandable: shared tokens, separate behavior, stable names, and one state owner. Self-contained means the delivered folder includes its dependencies and assets; a single-file export embeds those dependencies. Disclose deliberately remote resources.

Every visible control has a real behavior or a clear disabled state. Provide semantic landmarks, labels, focus visibility, keyboard navigation, and motion reduction. Do not substitute screenshots for editable UI. Use representative English content unless another artifact language is requested. Real data needs sources; synthetic data must be labeled.

Compare variations in one canvas or an in-page selector. Preserve prior iterations when useful without creating a maze of files. Evaluate hierarchy, alignment, density, text wrapping, states, and interaction after the first render. Verify the actual saved output over HTTP before delivery.
