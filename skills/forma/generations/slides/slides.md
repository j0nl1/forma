# Presentations

Create editable HTML slides using `deck.js` and its companion modules (or a bundled loader): each slide is a direct child `<section>` of `<deck-stage width="1920" height="1080">`. Use one story and one focal point per slide. Keep authored artwork fixed-size; the stage scales it and keeps navigation outside the artwork.

The stage supports keyboard navigation, thumbnails, slide order, deletion, restoration, hash navigation, fullscreen, print, and optional speaker notes. Add `<aside data-notes>` only when notes are requested. Keep source order meaningful and titles readable. Undo restores the previous deck state, including live slide nodes. Start the preview with `--deck-file deck.html` to save reorder, skip, duplicate and deletion actions to the actual HTML source. Unconnected static previews clearly report that edits stay in the page.

Read the full [deck runtime contract](../../references/deck-runtime.md) for all 44 effects, timing units, directions, group rules and verification status. Build animations use `data-anim="fade-in|fly-in|zoom-in|appear|path"` and browser equivalents of wipe, float, split, bounce, wheel, blinds, dissolve, shape reveals, spin, grow, shrink, pulse, and teeter. Reveal effects use browser geometries, including directional clips and animated gradient masks. Broader reference visual comparisons remain pending. Use `data-trigger="click|with|after"`. Use `data-delay`, `data-duration`, and `data-path` (SVG path data). Canonical `data-anim-duration`/`data-anim-delay` use milliseconds; older `data-duration`/`data-delay` use seconds. Repeats and eligible auto-reversal count their complete duration. With/after builds follow group timing. Base styles show the final layout. Reduced motion plays groups instantly and keeps click gating. Print shows authored base content; returning restores the current slide fully built. For more involved motion, use the timeline recipe.

Arrow keys and Space advance builds before changing slide. Text inputs keep their normal keyboard behavior. Verify first, middle, and final slides and print all slides. PDF is supported through [exports](../../references/exports.md). For editable or screenshot PowerPoint export with notes, read the [PowerPoint guide](powerpoint.md). Google Slides transfer requires an available connector; do not claim a conversion without a real configured integration. renderer-backed source bindings and richer presenter workflows remain required work in [known limitations](../../references/limitations.md).
