# Architecture

`skills/forma/SKILL.md` is the entry point. `references/harness.md` describes the shared capability-based workflow; `references/codex.md` and `agents/openai.yaml` provide optional Codex integration and UI metadata. The installer selects a skills root without changing the skill or any harness configuration. Existing `Codex*` globals, events and headers are local compatibility identifiers, not a host dependency. `project-types.json` maps thirteen modes to resources. `references/` holds original task recipes; `assets/starters/` holds editable runtime source. `scripts/` contains deterministic helpers and `scripts/lib/` their shared primitives.

The root contains documentation, tests, examples, and packaging. It is an npm workspace; the skill also has its own lockfile for independent installed-copy setup. Packages are pinned dependencies rather than opaque vendored bundles. A separate React 18.3.1 workspace preserves legacy component APIs alongside native React 19.2.4; the installed skill includes the same runtime workspace and its own complete lockfile.

Native DOM starters are classic scripts except the explicitly bundled 3D module and chart library entry. The canvas, deck, data overlay, text editor, image, document, social and live-file loaders import editable ES modules; copy their companions or bundle each loader for a single-file runtime. React systems and the continuous-composition animation engine use a local build step. Browser edits persist locally where supported. The motion preview service can write scene/playback literals to one explicitly selected HTML document, with same-origin tokens and content-version checks. The canvas preview service can write a versioned state sidecar beside one explicitly selected HTML document. It connects the first canvas in that document and leaves other canvases on browser storage. The deck preview service writes structural edits to literal slides in the first deck of one explicitly selected HTML file, with tokens, content versions, a count witness, serialized writes and in-memory undo. Static decks retain session edits. The typed tweaks service batches partial JSON edits into one root HTML defaults block, accepting the data-only legacy marker boundary as well as the native JSON-script binding. Static controls retain explicit browser/session state; draft handoff copies text for review. The text service injects its owned editor into one selected HTML response, preserves source markup through exact text ranges, and keeps failed drafts for review. Text, deck, tweaks and timing source writes use one shared per-file transaction queue with content checks before rename. The image service writes a fixed shared directory sidecar through versioned partial edits. Static slots read that state; explicit session slots retain browser state. Deck/canvas source previews connect image persistence for duplicate images, and standalone export embeds the shared state. The motion service also renders video from its selected document; no caller-selected URL or output path is accepted by the browser endpoint.

## Tools

- `config.mjs`: optional non-replacing profile initialization, read-only TOML validation and mechanical preference resolution. `lib/config-model.mjs` owns the strict schema, field precedence, backend-specific model/voice reset and required-only capability checks. A supplied snapshot describes current tools; the helper does not discover or authenticate them. Preferences guide new authoring and never override explicit existing audio manifests.

- `preview.mjs`: loopback HTTP, host validation, traversal and realpath checks; metadata-marked HTML receives the independently bundled plain-canvas runtime in its response; eligible raw HTML receives fixed-sheet detection without rewriting source.
- `project.mjs`: preserve metadata while registering assets.
The spoken-audio presets live in the shared recipe and focused references. They change editorial guidance, not provider selection or the existing episode schema. Preset settings, scene cues and provider/cache provenance remain companion data. The model interprets sources, authors the canonical script and reviews semantics; available tools perform extraction, scheduling and media operations. The local helper does not implement extraction, a voice-job queue, cache storage or absolute scene placement. Video narration integrates through the documented motion/audio export contract.

- `source-to-audio.mjs` (with the compatible `podcast.mjs` alias): offline script planning, source/reference checks, local clip decoding and standalone MP3/WAV assembly. The harness authors source-grounded scripts and chooses voice production with the user; the helper makes no speech or model requests. Estimated script timing and measured playback remain separate, and target misses are reported without trimming speech or padding the episode. Optional speech leveling measures each clip, controls loudness and true peaks, and verifies the encoded output before non-replacing publication; raw assembly remains available.
- `sound-effects.mjs`: offline sound-request plans and explicit configured MP3 generation; `sound-request.mjs` validates the provider request and bounded audio response, while `sound-audio.mjs` performs finite actual MP3 decoding before publication, and `sound-assets.mjs` owns contained reservations, non-replacing publication and audio provenance registration.
- `design-system.mjs`: read-only inspection/discovery, stable compilation, review generation, verified wiring and primary selection; `system-source.mjs` owns discovery, `system-contracts.mjs` owns syntax/declaration metadata, `system-review-data.mjs` prepares contained card assets and parsed shadow styles, `system-card-scripts.mjs` transpiles JSX/TSX without execution, `system-review.mjs` builds a standalone review. The editable `system-review*.js` browser modules own scoped execution, outline navigation and width-only fitting; `system-manifest.mjs` owns namespace/artifact checks and `system-bindings.mjs` owns staged portable imports, managed updates and merged project metadata. Named default class/function declarations retain separate public-name, local-name and default-import metadata; explicit default mappings keep their discovered contracts. Generated samples render the public runtime name. The HTML inliner accepts contained in-memory generated dependencies, so cards and seeds embed the current bundle/CSS before disk artifacts are replaced.
- `adherence.mjs`: read-only JavaScript/TypeScript/JSX/TSX and inline-HTML advisories from verified compiled policies. Separate source, binding and immutable-value analysis modules preserve scopes, origin-qualified contracts, finite variants and explicit unchecked dynamic inputs. Default warnings do not fail the command; strict mode does. It does not load project configs, follow HTML external scripts, execute input or write source.
- `figma.mjs`: offline inventory, raw mount, selected HTML, React component generation and system extraction. `figma-component-model.mjs` interprets component definitions, ordered/normalized axes, inherited references, defaults and collision advisories as data. `figma-component-jsx.mjs` converts owned render output into editable React elements with bound text/visibility/slots, root style/class props and per-instance SVG identifiers. `figma-components.mjs` emits JSX, sibling TypeScript declarations and variant provenance for the source compiler; local instance calls retain dependency closure and direct declared prop/variant assignments. `figma-component-instances.mjs` owns imports, swaps, scaled fixed-size calls, external placeholders and bounded baked cycles; `figma-instances.mjs` independently expands local masters and ordered override stacks without mutating decoded data. `figma-layout.mjs` restores horizontal/vertical responsive stacks, grow/stretch, inferred hug dimensions, padding/gaps/wrap and min/max sizes. `figma-grid.mjs` restores ordered tracks, gaps/padding and direct-child anchors/spans/self-alignment while retaining the source sizing distinctions. `figma-component-synthesis.mjs` plans bounded numbered text/icon slots with declared-binding and collision gates; emitted bodies register actual public JSX/declaration slots. Direct synthetic instance overrides retain local swap dependencies and source scale/resize styles. Grow/stretch instance calls override master dimensions with explicit `auto`; expanded call snapshots retain GRID placement fields. `figma-vector-network.mjs` decodes closed region loops only for generated component geometry when saved fill/stroke outlines are absent; raw rendering and masks keep their source geometry path. Generated ordinary text uses literal font text, while `figma-component-icons.mjs` emits recognized icon-font outlines as flow SVG with source-rounded coordinates, currentColor and live root styles.
- `lib/figma-paints.mjs`: ordered visible fill layers, native blend modes, real text clipping and SVG solid/linear vector layers. Separate `figma-paint-gradients.mjs` and `figma-paint-images.mjs` own transformed gradient geometry and contained image backgrounds. Per-layer image alpha and FILL/FIT/TILE/CROP/STRETCH survive HTML, PNG and copied reviews; unknown inputs and approximation boundaries remain explicit warnings.
- `lib/figma-strokes.mjs`: inspected box border/alignment, independent side widths and dashed CSS fallback. Border shadows precede effect shadows in one stack. `lib/figma-geometry.mjs` independently decodes finite command coordinates, keeps ODD/EVENODD holes and renders saved fill/stroke outlines, including zero-height lines, with contained inside/outside stroke masks. Shared paint resolution keeps fill/stroke gradient IDs separate; overlapping geometry follows per-path paint order. Exact box dashes and complex stroke layouts remain explicit advisories.
- `lib/figma-text.mjs`: saved glyph paths, positioned/scaled/rotated silhouettes, node-coordinate paints and inside/center/outside glyph strokes. Contained image backgrounds and masked backdrop blur preserve holes; literal accessible text remains embedded. `figma-text-style.mjs` owns font metadata, spacing/line-height units, decorations/case, OpenType/variation fields and literal character style runs. `figma-text-runs.mjs` retains ordered/unordered prefixes, indentation/numbering resets and newline-aware character offsets. Unsupported layout and per-glyph decoration/paint cases remain explicit advisories.
- `lib/figma-masks.mjs`: sibling mask runs, hidden-mask boundaries and flattened affine contour unions. Saved vector/glyph geometry, rounded boxes and ellipses clip following siblings in contained SVG definitions; unsupported alpha/luminance compositing and missing contours remain explicit advisories.
- `lib/figma-effects.mjs`: independent shadow-stack and blur rendering for offline imported nodes; normal boxes retain inset/drop spread, while text/solid-vector alpha silhouettes use CSS drop shadows and contained SVG inner filters. Filters travel in selected HTML and compiled reviews; unsupported effect modes remain visible warnings.
- `build.mjs`: local JSX/TSX/module bundling.
- `export.mjs`: parsed HTML/CSS inlining, Chromium PDF/PNG, deterministic video, and native/image-based PowerPoint from discrete HTML decks. `pptx-capture.mjs` measures source objects and animation membership; `pptx-layers.mjs` captures isolated CSS paint with exact style restoration; `pptx-media.mjs` snapshots bounded local media and normalizes generated media XML/shape IDs; `pptx-media-playback.mjs` prepares bounded source-range/rate/gain copies with local FFmpeg and reports source/embedded hashes; `pptx-media-timing.mjs` writes native media loop and activation intent with explicit receiver diagnostics; `pptx-controls.mjs` performs a bounded visual-settle check for Chromium media controls before poster capture. `pptx-fonts.mjs` loads explicit font snapshots before measurement and embeds used family faces as EOT with coverage diagnostics; `pptx-fonts-metadata.mjs` validates SFNT names, styles, glyph maps and embedding rights. `pptx-motion.mjs` translates the shared HTML effect model and build schedule into native PresentationML; `pptx-motion-affine.mjs` compensates authored base transforms and pivots, and `pptx-motion-compose.mjs` samples bounded nested builds on disjoint editable artwork groups, `pptx-motion-repeat.mjs` splits explicit repeat resets, and `pptx-motion-compositing.mjs` gates native opacity and leaf-mask ownership. `pptx-motion-frames.mjs` captures bounded transparent fade/wipe subtree frames using the shared effect model and adds picture visibility changes to the same main sequence; source effects are reported separately as native, raster or static animations. Conditional manual-video covers share their native image relationship and are hidden by the same click command that starts playback. Unsupported-target and receiver diagnostics remain explicit.
- `lib/pdf.mjs`: current-runtime paper choices, print layout readiness and real PDF output.
- `lib/audio.mjs`: frame-grid media inventory, temporary local source snapshots, source-range/pitch-preserving loops and AAC/Opus mixing; the final video stream is copied during muxing.
- `lib/video.mjs`: frame-by-frame authored timeline capture, decoding waits and paused-video surface resubmission after visibility paint. Frame callback requests are canceled rather than awaited so held/quantized source times remain finite; FFmpeg encodes the captured pictures and the audio helper mixes local marked tracks.
- `lib/font-network.mjs`: caller-configured read-only font/stylesheet/fetch origins, per-hop redirect checks and CSS rebasing against the final response URL; the connected editor uses server-start configuration rather than browser-supplied grants.
- `verify.mjs`: runtime and screenshot probes, not semantic flow verification.
- `tools/install.mjs`: staged local copy and conflict-aware managed update.

Source updates use sibling temporary files and atomic rename. Generated sound and spoken audio use atomic non-replacing publication; podcast output is linked from a private sibling temporary directory after final decoding. Multi-file generation is not a database transaction; use fresh folders. Compiler output deliberately replaces its own generated files.

The review payload is a hashed compiled artifact. Review generation reads verified copies, embeds the runtime and component bundle once, and mounts cards in independent shadow roots. CSS sheets and font rules are deduplicated. Classic card scripts execute only in the browser through scoped document/window proxies; declaration getters retain lexical state across script blocks and inline handlers. The 3 MiB local runtime-asset map preserves source-relative fetches in both review and portable card pages. This isolation is for composition, not security.

## Trust boundary

Figma schemas are interpreted as data with ByteBuffer, never compiled into JavaScript. Inspection does not evaluate source. Browser previews execute page scripts, so reviewed source and an appropriate environment remain necessary. Browser exporters require loopback HTTP input and keep subresources local by default. Explicit `fontOrigins` grants allow GET/HEAD font, stylesheet and font-embedding fetch requests from selected HTTP(S) origins, without granting scripts or remote writes. Font/stylesheet requests and configured remote embedding requests validate redirect targets before following them. Ordinary authored browser pages retain their own network behavior; the stage's `fontOrigins` prop governs embedding, not a browser sandbox. Harness browser tools have their own permissions. This package is not a sandbox for arbitrary imported code.

## Design-system runtime selection

Read-only authoring analysis identifies free browser React globals, safe legacy source namespaces, old DOM calls and recognized CDN declarations. Source imports and namespace references are transformed into module dependencies without evaluating design source. A package-export reader parses pinned CJS export assignments as data. Browser facades select one actual React/DOM/JSX pair per exact version through `window.CodexDesignRuntimes`, allowing several independently compiled systems to compose stateful components in one root. Raw React/DOM package internals resolve within their own matched dependency pair; consuming source imports use the shared facades. React 18 cards replace recognized React/Babel declarations with the locally compiled pair and a first-script bootstrap. Unsupported declarations fail compilation before artifacts are written.

## Design-system CSS inventory

`system-css.mjs` reads the contained PostCSS import closure, declarations, selectors/conditions, asset references and font faces without evaluating source. Shared owned CSS URL/escape parsing preserves source-relative font paths. `system-css-values.mjs` resolves aliases and nested fallbacks while retaining quoted/comment data. Separate token/font metadata modules retain every declaration's provenance and distinguish advisory classification/font gaps from structural errors. The compatibility token map remains the last textual definition, not a complete cascade calculation. Compiled source CSS is preserved. `system-token-review.mjs` renders typed previews and font metadata, with scrollable narrow tables. The review payload always embeds global font rules, including HTML-only/token-only systems. Imported manifests and guides retain the inventory after source deletion.

`system-type-graph.mjs` builds a read-only declaration dependency graph and an in-memory TypeScript program. Its host reads contained source files and the pinned compiler's standard declarations; it does not read project compiler configuration, resolve external packages, emit or execute code. Missing/escaping local imports fail inspection, while external type gaps remain explicit advisories. Shared imported declarations are exempt from orphan checks. `system-type-contracts.mjs` retains generic/mapped properties, resolved types, documented defaults, finite variants, source provenance, signatures and separate conditional union alternatives. The manifest, hashed contract closure, review and copied guide retain the resulting metadata. These contracts do not replace a full application type check or comprehensive adherence enforcement.

## Public component imports and adherence

`system-export-graph.mjs` resolves contained runtime re-exports through an in-memory TypeScript program, independently of declaration-contract analysis. Named and local imported aliases, cyclic star barrels and module namespace values retain their owning source, actual import binding and public provenance. Discovery merges owner contracts with alias-specific sibling declarations/usage; later forwarding barrels preserve that metadata. Type-only values stay out of the runtime catalog. Missing, escaping and ambiguous local exports fail read-only inspection before compilation writes artifacts. The host reads selected sources/declarations only, without project configuration, external package lookup, emission or execution. External export inventories produce explicit advisories. Complete export maps, package/path aliases, asset-module exports and additional language cases remain pending.

Compilation emits a hashed native JSON adherence policy and, when a bundle exists, a public ES module entry. The manifest uses `adherence` and `moduleEntry`; managed copies, binding metadata, verified wiring and local guides retain both. The module loads the owned compiled browser bundle and exports its matching React renderer, Components, named exposed components/constants and default registry. Browser-native consumers must use plain JavaScript; JSX/TSX and standalone HTML consumers bundle their entry first. Token CSS stays separate. Complete package export maps are not supported.

Adherence policies preserve the inspected raw-hex/raw-pixel, internal-import, prop-allowlist and finite-variant advisory contracts without a hosted configuration protocol. Immutable literals and spreads have conservative static checks; dynamic or mutated input is reported as unchecked. Unknown inherited interfaces leave the full allowlist unchecked instead of rejecting legitimate inherited props. Several systems keep independent origins, and local shadowing does not bind unrelated components. This is an advisory authoring aid, not comprehensive CSS, JavaScript-flow, application typing or visual-fidelity enforcement.
